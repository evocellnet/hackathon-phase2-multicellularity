# Eukaryote gain-ladder plan (restricted to the branches the tests use)

Generated by `scripts/gain_ladder.py plan` before the eukaryote HOGs exist (PREREG Dev-2/Dev-3).

* Branches: 107 (85 internal, 22 terminal tip stems), from `mcell.branchstats.build_branch_table` on `data/guide_tree_euk.nwk` (identical to the Ancestra input tree): every transition branch in `data/transitions.tsv` (stems, nested/grey/reversal stems, path-stem edges; primary, secondary, exploratory, reversal), every control-pool branch U, and the edge above each. List: `runs/gainladder/euk/branches.tsv`.
* Model (prokaryote run): gains on an internal branch = mean proteome size of the clade x 0.0087 x n_desc^0.91 (log-log fit, 41 prok internal non-root-child branches); tip stems = 0.117 x proteome (median prok leaf); 2.01 queries per gain (prok two-pass); 0.53-1.1 CPU-s per query (prok actual - random-protein pilot, very-sensitive).
* **Estimated gains: 168,474** (134,622 internal, 33,852 on tip stems); **queries ~338,861**.
* **CPU: 49-104 CPU-h = 2.5-5.2 h at 20 threads** (nice 5). Uncertainty is at least x2 either way: eukaryote HOG splitting at the 7,500-gene family cap and deep, long stems probably raise the gain rate above the prokaryote model.
* Output size: ~157 hits per pass-1 query (prok) to 640 (random eukaryote proteins): 53-217 M rows, 0.9-3.6 GB gzipped.

## Launch

`runs/gainladder/euk/run_euk.sh` (started with nohup) waits for `runs/euk_fast/DONE.json` or `runs/euk_fast_p/DONE.json`, uses the first one present (records which; if both exist it checks that the two `hogs.orthoxml` are byte-identical), then runs `prepare` -> `search --two-pass --threads 20 --nice 5` -> `classify` (-> `arch` if Pfam tables exist) and writes `results/gainladder/euk/DONE.json`. Log: `runs/gainladder/euk/run_euk.log`.
