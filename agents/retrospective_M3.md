## 2. What worked well and should continue? (6 points)

1. **Independent adversarial review before results.** Three design rounds (5 + 3 reviewers + final audit) changed the primary gain statistic (raw Ancestra gains inflated 2.1-2.6x), the transition coding (path stems, eligibility rule, D5/D7) and the null (relabelling anti-conservative, 14.5% at alpha 0.05; D6). Frozen as prereg-v1 at 14:20, 2 h after start.
2. **Calibrating methods on simulations and the real tree, and reporting failed acceptance tests as outcomes.** Split-repair failed its criterion and was dropped (Dev-3); null calibration led to the parametric bootstrap (Dev-1, FPR 0.04-0.05 vs 0.08-0.28); tree calibration produced a quantitative interpretation rule (Dev-4, 2.2x threshold) before seeing results.
3. **Deviation log with reason and results-visibility status.** Every post-freeze change (Dev-1 to Dev-4) states why and whether results were seen; hash file PREREG_HASHES.tsv plus freeze/verify script make tampering detectable.
4. **Separate agents for verification found a real bug early.** The shadowing of the volvocine path stem in mcell.branchstats was found by an independent agent before eukaryote results (decision log, t~7 h), commit "Fix: primary row's stem_path wins".
5. **Positive controls and dry runs on the cheaper prokaryote set before the expensive eukaryote run.** "prok dry run: P1, P2 recovered" validated the scorer/driver; the patched Leiden wrapper was verified byte-identical on prokaryotes; DIAMOND sensitivity trade-off (Dev-2) measured on 500 real proteins and rechecked on 200 gains.
6. **Parallel, early start and honest expectation-setting.** Environment/downloads launched at t=0; dataset build before design review ended (D1); written power expectations before results (M2); unfindable resources (Eukaryoma, Sorogena) flagged without blocking (D2); fallback when AFDB throttled (Swiss-Prot reference with clade exclusion, 10 min after the structure pipeline commit).
